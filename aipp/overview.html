AI PUBLICATION PROTOCOL EXPERIMENT

A reviewed knowledge layer for AI.

Northstar AIPP combines writer-approved documentation with registered sources and reviewed AI-only context. It gives AI systems structured knowledge, provenance, lifecycle metadata, and explicit uncertainty without replacing the human documentation.

How it works

Human documentation+ Registered sources+ Reviewed sidecars→ Validate and compile→ Published AIPP object

Features and strengths

Writer controlled

Writers select sources, revise the human draft, and approve sidecar knowledge before publication.

Source aware

PRDs, ERDs, wikis, Word files, presentations, Jira tickets, API contracts, code, and configuration use consistent metadata.

AI-only context

Reviewed edge cases, support guidance, configuration behavior, and implementation details can be available to AI without crowding the human guide.

Provenance

Statements cite registered sources with authority, ownership, lifecycle, locator, retrieval method, revision, or content hash.

Conflict signaling

Contradictory sources remain explicitly unresolved instead of being silently reconciled or hallucinated.

Automation ready

A versioned schema, validator, compiler, discovery document, feed, and CI publication make the contract repeatable.

Where it helps

  • Grounded documentation assistants and retrieval systems
  • Support and troubleshooting questions that exceed public documentation
  • Configuration, API, and edge-case answers requiring precise sources
  • Reviewable knowledge updates tied to normal pull-request workflows
  • Comparisons between rendered docs, llms.txt, and richer structured context
