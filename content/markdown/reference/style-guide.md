# Documentation style guide

This short guide provides consistent editorial rules for every rendering of the Northstar documentation.

## Write for action

Start a procedure with a verb and explain the outcome. Prefer "Create an environment" to "Environment creation."

## Use precise, respectful terms

Use `allowlist` instead of `whitelist` and `blocklist` instead of `blacklist`.

## Do not minimize complexity

Avoid words such as "simply" and "obviously." They can make a necessary task feel like a reader's failure. Explain the action, prerequisites, and expected result instead.

## Treat automated checks as feedback

An automated style checker can catch repeatable wording and terminology issues. It cannot verify product behavior, replace a technical review, or decide whether a page is useful.
